System Overview
NCGN (Neural Concept Graph Network) is a hybrid cognitive architecture combining fast associative propagation (System 1) with deliberative reasoning (System 2). It models cognition as signal propagation through a weighted directed graph, where concepts are nodes and associations are weighted edges.

Design Tenets
Separation of Concerns: System 1 (reflexive) ≠ System 2 (deliberative)
Data-Oriented Design: All state in contiguous arrays, not object hierarchies
Cache Optimization: Structure-of-Arrays for SIMD vectorization
Lazy Computation: Rebuild matrices only when topology changes (dirty flag)
Thread Safety: Lock-protected index registry for concurrent access
Design Philosophy
Dual-Process Theory Implementation
NCGN implements Kahneman's dual-process theory:

Aspect	System 1 (Propagation)	System 2 (Reasoning)
Speed	Fast (< 1ms per tick)	Slow (100-1000ms)
Method	Matrix multiplication	LLM inference
Energy	O(E) sparse operations	O(N²) transformer
Role	Association, intuition	Logic, planning
Trigger	Always active	On-demand
Output	Activation patterns	Graph updates

Component Details
1. GraphTopology: Integer-Indexed Graph
Purpose: Manage graph structure with automatic label↔index synchronization.

Key Feature: Rustworkx uses integer indices only. IndexRegistry maintains perfect bidirectional mapping.

# Thread-safe mapping
class IndexRegistry:
   _label_to_idx: Dict[str, int]
   _idx_to_label: Dict[int, str]
   _lock: threading.Lock
Critical Property: When nodes are deleted, Rustworkx leaves "holes" and reuses indices. Callers MUST zero the state arrays at deleted indices using CognitiveState.zero_index().

Operations:

add_concept(label) → Returns integer index
add_connection(src, tgt, weight) → Creates/updates edge
get_adjacency_data() → Returns (sources, targets, weights) for matrix construction
Complexity:

Add node: O(1)
Add edge: O(1)
Lookup label→index: O(1) hash table
Extract adjacency: O(E) where E = edge count
2. CognitiveState: Structure-of-Arrays
Purpose: Store all cognitive state in cache-optimal contiguous arrays.

Memory Layout:

activations:          [0.5, 0.3, 0.0, 0.9, ...]  float32[N]
thresholds:           [0.75, 0.75, 0.8, 0.6, ...]  float32[N]
refractory_counters:  [0, 3, 0, 5, ...]            int32[N]
resting_potentials:   [0.0, 0.0, 0.1, 0.0, ...]   float32[N]
novelty_scores:       [1.0, 0.95, 0.88, 1.0, ...] float32[N]
embeddings:           [[0.2, 0.5, ...], ...]       float32[N × 384]
Why float32? 2× memory bandwidth vs float64, sufficient precision for activations.

Dynamic Capacity: Pre-allocated, doubles when full (amortized O(1) growth).

CSR Matrix Caching: Adjacency matrix is rebuilt ONLY when topology changes:

def synchronize_matrix(self, topology: GraphTopology) -> None:

       return  # No rebuild needed

Access activation: O(1)
Resize capacity: O(N) amortized O(1)
Rebuild CSR matrix: O(E + N) where E = edges, N = nodes

Propagation Algorithm
Input: External injections, Number of steps
Output: Active concepts dictionary

1. Synchronize CSR matrix if topology dirty
2. For each step:
  a. Apply external input buffer
  b. Decay: A ← A × (1 - δ)
  c. Propagate: A ← A + W @ A × α
  d. Normalize: A ← A / (1 + β × ΣA)
  e. Sigmoid: A ← σ(6A - 3)
  f. Find firing nodes: F = {i | A[i] > threshold[i] ∧ R[i] = 0}
  g. Apply refractory: R[F] ← refractory_period, A[F] ← 0
  h. Mask refractory: A ← A ⊙ (1 - R_mask)
  i. Decay refractory: R[R>0] ← R[R>0] - 1
  j. Seizure damping if ΣA > θ_seizure
  k. Clamp: A ← clip(A, 0, 1)
3. Return active concepts {label: activation | activation > threshold}
Complexity: O(E + N) per tick where E = edges, N = nodes (sparse matrix-vector multiplication).

Auto-Genesis (Structural Plasticity)
Co-occurrence tracking without LLM:

def auto_learn(self, active_indices: Set[int], threshold: int = 5) -> int:
   # For all pairs of active nodes
   for i, j in combinations(active_indices, 2):
       co_occurrence_counts[(i, j)] += 1
       
       if co_occurrence_counts[(i, j)] >= threshold:
           # Auto-create edge!
           topology.add_connection(label_i, label_j, weight=0.3)
Rationale: If two concepts repeatedly co-activate, they should be connected.

Learning Algorithm
Input: Reward modulator M, Active threshold
Output: Number of synapses updated

1. Calculate active set A = {i | activation[i] > threshold}
2. If M > 0, run auto_learn(A) for structural plasticity
3. If no edges or |A| < 2, return 0
4. For each active pre-synaptic node i ∈ A:
  a. For each outgoing edge (i→j) where j ∈ A:
     b. Δw ← η × M × activation[i] × activation[j]
     c. w_ij ← clip(w_ij + Δw, w_min, w_max)
     d. If Δw > 0, reinforce confidence
5. Return update count
Complexity: O(E_active) where E_active = edges between active nodes (typically << E).

Design Patterns
1. Data-Oriented Design (DOD)
Problem: Object-Oriented Programming (OOP) causes cache misses.

Traditional OOP (cache-inefficient):

class Neuron:
   def __init__(self):
       self.activation = 0.0
       self.threshold = 0.75
       self.refractory = 0

neurons = [Neuron() for _ in range(10000)]

# Cache-inefficient: neurons scattered in memory
for neuron in neurons:
   neuron.activation *= 0.9  # Cache miss every iteration
DOD (cache-optimal):

activations = np.zeros(10000, dtype=np.float32)
thresholds = np.full(10000, 0.75, dtype=np.float32)
refractory = np.zeros(10000, dtype=np.int32)

# Cache-efficient: contiguous memory access
activations *= 0.9  # Vectorized, SIMD-optimized
Benefits:

Contiguous memory → fewer cache misses
SIMD vectorization (AVX-512 on modern CPUs)
10-100× faster for large N
2. Structure-of-Arrays (SoA)
Variant of DOD: Separate arrays for each property.

Array-of-Structures (AoS) - cache-inefficient:

neurons = np.array(
   [(activation, threshold, refractory) for ...],
   dtype=[('a', 'f4'), ('t', 'f4'), ('r', 'i4')]
)
# Access: neurons['a'] - strided access
Structure-of-Arrays (SoA) - cache-optimal:

activations = np.array([...], dtype='f4')
thresholds = np.array([...], dtype='f4')
refractory = np.array([...], dtype='i4')
# Access: activations - contiguous
Why? Processing often touches ONE property at a time. SoA ensures all data for that property is contiguous.

3. Dirty Flag Pattern
Problem: Rebuilding CSR matrix is expensive (O(E + N)).

Solution: Mark topology "dirty" when changed, rebuild only when needed.

class GraphTopology:
   def __init__(self):
       self._dirty = False
   
   def add_connection(self, src, tgt, weight):
       # ... modify graph ...
       self._dirty = True
   
   def mark_clean(self):
       self._dirty = False

class CognitiveState:
   def synchronize_matrix(self, topology):
       if not topology.is_dirty:
           return  # Skip rebuild
       
       # Rebuild CSR matrix
       self._adj_csr = build_csr(topology)
       topology.mark_clean()
Performance: Eliminates redundant matrix builds between propagation steps.

4. Lazy Initialization
Problem: Loading large models (LLM, SentenceTransformer) is slow.

Solution: Delay initialization until first use.

class SemanticLayer:
   def __init__(self, model_name):
       self._model = None  # Not loaded
       self._model_name = model_name
   
   @property
   def model(self):
       if self._model is None:
           # Load on first access
           self._model = SentenceTransformer(self._model_name)
       return self._model
Benefits:

Fast Brain instantiation
Don't load unused components
Parallel startup possible
5. Registry Pattern
Problem: Rustworkx uses integer indices, but humans use string labels.

Solution: Bidirectional registry with thread-safe lookups.

class IndexRegistry:
   def __init__(self):
       self._label_to_idx = {}
       self._idx_to_label = {}
       self._lock = threading.Lock()
   
   def register(self, label, idx):
       with self._lock:
           self._label_to_idx[label] = idx
           self._idx_to_label[idx] = label
   
   def get_index(self, label) -> Optional[int]:
       return self._label_to_idx.get(label)
Performance: O(1) lookups in both directions.

Conclusion
NCGN is a hybrid cognitive architecture that:

Separates concerns between fast association (System 1) and deliberative reasoning (System 2)
Optimizes for performance using data-oriented design and cache-optimal memory layouts
Learns from experience using biologically-inspired 3-factor Hebbian plasticity
Grounds in semantics using modern embedding models
Verifies knowledge using confidence tracking and conflict detection
The architecture achieves real-time performance (< 10ms per cognitive tick) while maintaining biological plausibility and interpretability.
